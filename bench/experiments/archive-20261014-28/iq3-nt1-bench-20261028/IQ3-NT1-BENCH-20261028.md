- VNNI／gather 狀態：STRATA_AVXVNNI=1 已編入 iq_avx2.cpp（build.make 確認）；iq256_variants()=3（gather+VNNI 都可跑）；P-core 上現行自動選擇 iq256_variant()=3，E-core LP15 為 2（VNNI、無 gather）。

## 正確性
- B、C、D 彼此輸出逐位相同，與 A 不同（加總順序不同，預期）：max_abs 7.15e-7（max|A|=3.72，約 1.9e-7 滿刻度）、max_rel（|d|/(|A|+1e-6)）7.4e-4（出現在接近 0 的值）、66×640 = 42240 個值中 22177 個（約 52%）不同。
- A 在所有重複間逐位相同（每次比對該 pass 最後一個 expert／warm expert 與基準）：YES。

## 判讀
- 最佳臂 B 在兩個 P-core LP、stream／warm 都約 1.15–1.17×；落在 1.15–1.30 灰區，stream 值（1.172、1.174）剛好高於 1.15 下限一點點。
- stream ≈ warm（A 5.08 vs 5.25 GB/s）→ 單核 kernel 是解碼算力受限，不是 DRAM；此處 A 單核 5.1 GB/s，高於 WORKER-SKEW 引擎內量到的 3.8 GB/s（資料、活化與記憶體競爭條件不同，絕對值不能直接互換）。
- 增益主要來自 VNNI（B 對 C 約 +4%）與 gather（C 對 D 約 +10%）；D 與 A 幾乎相同。
- E-core：gather 臂比 ggml 慢約 4 倍，只有 D 接近（0.90×）；現行 cpu_gather_fast_here 在 E-core 不用 gather 是對的。所以任何新 kernel 在 E-core（約佔 27% 列）都無增益，且混用兩種 kernel 會讓各核四捨五入不同（IQ3_S 的 MT_MIN 註解就是在避免這件事）。
- Amdahl 粗估（沿用 IQ3_KERNEL_PROBE：gate/up 約 8.8 ms／32.8 ms window）：全部 P-core 1.17× → 省約 1.3 ms ≈ +4%，E-core 不受益時更低；而且 B 與 ggml 不是逐位相同，要上線需另寫位元相同 nt=1 kernel。這是估算，不是量測。
