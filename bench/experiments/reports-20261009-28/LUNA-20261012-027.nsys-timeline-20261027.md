### 4. 成因（證據強度）

| # | 成因 | 量測 | 證據 |
|---|---|---|---|
| 1 | host 執行緒對 SSD 做**同步大讀取**（FileExpertSource::prefetch → fill_many → read_direct，overlapped ReadFile 後等待並 memcpy）。呼叫位置在 expert_pool_dispatch_multi 建 job 與 pool publish **之前**（約 line 3814），讀取期間 9 個 worker 全閒置 | 每 window 4.32 次大讀取、7.7 MB，平均 1.79 MB；合計 4.17 GB；每 window 同步等待 7.29 ms（A）；W（僅 WPR）約占 window 10.5%，A 約 12.4%；attempt 3 為 13.5%；各 run 讀取次數 4.3–5.8/window 一致。long 層 61% 含大讀取；long 層的 6.4 ms/window 與大讀取重疊。DiskIo 服務時間 p50 0.60 ms、p90 1.18 ms、p99 24.6 ms；69 次 ≥5 ms | 【量測，強】跨三個 run、符號+行號+ETW 對得上 |
| 2 | pool park/wake 停頓：worker 以 AlertByThreadId 休眠，喚醒延遲量化在約 15.6 ms 計時器刻度，像 lost-wakeup | 5.38 ms/window（A） | 【量測 + 部分推論，中】A 內有一部分是追蹤造成；正式環境發生率未知 |
| 3 | 硬缺頁（對映檔頁面讀入） | A 6.4% vs W 0.4% 的 window 時間 | 【量測，強】大半是 nsys 取樣的 artifact，非正式環境成因 |
| 4 | host 僅 kernel 的樣本（USB xhci/hidclass DPC、ISR、少量 ntfs/fltmgr）在 host 核心 0 | A 3.2 ms/window | 【量測】來源；對 production 影響【推論，未解】 |
| 5 | 被其他程式搶占 | 0.72 ms/window（Aac*Hal、ExitLag、Cef 等） | 【量測，小】 |

說明：long 層中 1196 層（39%）沒有大讀取，卻貢獻 8.84 ms/window 的 post，主要落在成因 2/4/5；因此「所有長尾都是 SSD」不成立，SSD 同步讀取約占長尾的 6.4/19.8 = 32%（A）。post 對讀取量迴歸斜率 1.11 ms/MB（相關 0.14，弱），顯示延遲主要受 p99 長尾（24 ms 級）影響，而非吞吐量。

### 5. 不改輸出的修法（【推論】，需另行授權才可實作與量測）

| 修法 | 上限 | 備註 |
|---|---|---|
| 把 prefetch 的檔案讀取與 resident 專家的 job publish 重疊：先 publish 常駐命中的 job，讀取回來後再 publish 缺漏 job；讀取在 host 上做，pool 先算 | 同步讀取 7.3 ms/window（A）或約 10.5%×42.6≈4.5 ms（W）；實得約是 resident 專家算力時間與讀取重疊的部分，未量測 | 位元級輸出相同（只改順序） |
| 把大讀取拆成多個 overlapped ReadFile 同時送出（現為單一個等一個） | 受限於 SSD 服務時間 p50 0.6 ms；對 p99 24 ms 長尾無保證 | 輸出相同 |
| 修 pool park/wake（縮短 spin 後再 park 的門檻，或喚醒時用 SetEvent 取代 WaitOnAddress 的慢路徑） | 上限 5.4 ms/window（A，含追蹤成分），實際可能明顯較小 | 輸出相同；先在無追蹤下重測發生率 |
| 不採用：降低缺頁（nsys artifact，W 僅 0.4%） | — | |

這些都不改專家選擇、不改數值，因此是 exact-output；效益上限不可相加（成因 1 與 2 部分重疊）。

### 6. 限制

- A 被追蹤擾動嚴重（58.35 vs ref 37.17 ms/window），A 的 host stall、缺頁、park/wake 數字都偏高；W 與 ref 較接近正式環境。
- 三個 run 的 token 序列、window 組合不同，跨 run 只比較比例。
- DiskIo 服務時間的單位（100 ns）為推定。
- CSwitch 酬載 tracerpt 未解碼，只用 nsys 的 SCHED_EVENTS。
- 未量測的：實際重疊修法的節省、pool 停頓在 production 的發生率、USB DPC 的真實影響。
