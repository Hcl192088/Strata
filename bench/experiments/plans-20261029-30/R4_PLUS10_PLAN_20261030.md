## 實測後決策

P1 NR2/NR4 與 P2 full-H LUT 的已測原型均更慢，停止延伸；R4 暫停全面整合。P3/P4 已完成三題 instrumented 成本診斷，但沒有完成新 kernel／融合或整機 +10% 驗證。下一優先是核對原排程下 CPU pipeline 與 GPU 的可省成本，只選一個有足夠 headroom、能守住品質契約的具體候選。

目前沒有已通過證據門的 +10% 候選。waitCPU 不等於純 CPU 算術；profile 混合投影組不等於 Q6-only，也不是所有 dense 的完整成本。一般 P/E 平衡已有舊反證，不重新包裝成新大方向。

## 原設計紀錄（排序已由修訂版取代）

保留 R4 為已經取得初步證據的主線，但不把它當成唯一方法。其他大方向依序是：

| 優先級 | 尚未測過的結構方向 | 與既有工作的差異 | 進入實作前要證明什麼 |
|---|---|---|---|
| P1 | 原 native layout 的跨 row×token 新 CPU microkernel | 既有核心已共用同 row 的多 token；這項同時處理多 row，保留原檔案／GPU格式，免除 R4 admission 轉換 | compiled correctness、減少的 decode／load／spill，以及完整 expert 的加權 critical-path 收益 |
| P2 | activation-dependent codebook dot LUT | 現有 weight grid 只把量化碼解成權重；這項對當次 activation 先建立小組整數點積表，跨 row／expert 重用 | 五種格式的實際 pattern 數、建表攤提、查表與 cache 成本；不可先假設 LUT 比 VNNI 快 |
| P3 | GPU 原量化 dense 權重的新同容量佈局與 tile kernel | 現成 Q6 packed 只適用 heads；本模型 head 是 Q5_K，不能直接開旗標。研究真正的 Q6 dense consumer 與 prefill／decode 共用格式 | 目標矩陣的實際串行時間夠大、同 VRAM 無第二副本、全部 consumer 可用相同 lossless representation |
| P4 | GPU 關鍵路徑的新跨階段資料流融合 | 找新的重複讀寫／中間 buffer／同步成本；不是重開已測 LFUSE、QFUSE 或小旗標 | current adjacency 與分段時間，明確指出未被現有路徑消除的操作及可省 ms/window |
| 配套 | CPU／GPU／SSD 共享可逆 R4 格式 | GPU 直接讀 packed rows，避免每次 admission 反轉換；需要檢查所有 consumer | 不增容量、不改值、無 runtime fallback。省去新加入的轉換不能算成相對 current best 的獨立收益 |

**品質底線**：以保留每個輸出原有的整數結果、浮點累加／rounding 與狀態更新為優先。只證明「相同權重／小 float 誤差」不足以通過。若某方案無法保留算術契約，就停在 QUALITY_UNCONFIRMED，不能繼續把它列為已確認不影響品質的方案。

**大收益門檻**：歷史標尺約需省 3.37 ms/window 才有整體 +10%。CPU 模型約需完整 compute 1.4×，GPU 則需要先找到足夠大的真實串行段。這些是所需改善量，不是收益預估；不把數個候選的孤立百分比直接相加。

- 這次授權包含計畫、隔離實作與測試；不自動晉升 best 或改正式 launcher。若需暫停 API 做隔離整機 A/B，僅限已核對的 Strata benchmark/service 程序，保存原設定並用既有 finally 復原；不得停止無關程序。CPU 小篩時保留原 API，確認 idle；若有使用中請求，停在 gate。

## 4. +10% 的成本尺與 checklist 七題

1. **目標／差距**：歷史 C47.316 → +10%52.048；約省1.921ms/token。最新 live 重新啟動核對中，沒有當輪新 C 速度。正式門檻相對同期 C；不能宣稱目前仍是47.316。
2. **最近時間拆解**：2026-10-29 同 source DIAG 的 pipeline14.6818、join4.4068、LRU0.9114ms/window；完整1114windows、53472layer-windows。GU/down 在 pipeline 下子 counter 為0，不能從CPU總數假裝拆出純IQ算術。這份拆解與當輪 binary/source identity 若改變，先標舊資料，重核適用性；不同 DIAG SHA 不能當效能 control。
3. **針對哪段／上限**：主線攻 GU 解碼/整數點積與 nt2/3 排程；down、I/O、GPU 固定成本須保留。舊固定I/O模型全CPU compute1.3×只估+8.06%，1.4×約+10.16%，1.5×約+12.05%；模型尺度包含ready prefix且未含新轉換。這是必要量級尺，不是 R4 v2 上限或收益預測。若只有少數型別提升，必須取得實際 format×nt×core 權重與 critical-path 歸屬，不能以48層均權或73%P核舊數外推。
4. **同家族連續幾輪**：最近為lossless、RAM quota/LFUSE、SSD arrival、R4等不同結構；LFUSE是GPU開關家族第3筆且負，不再掃。PIN/PCIe家族已3筆負／雜訊結案。R4 v2有明確未接上的ISA／查表證據，是同結構的實作修正，不靠換參數續命。
5. **是否重做無新證據項目**：MT1部署、全域MT_MIN/gather、worker/affinity/power/spin、PIN/PCIe、spec-split、LFUSE、已測3 codecs、SSD arrival原工作量重疊不重跑。GPU其餘4個screen只過有限數值、尚無有效speed結論；只在第7節有限清單中補證據，不把原bundle垃圾輸出的+8.93%當正面依據。
6. **結構方向是否考慮**：miss預測/配額有成本或heldout不足；CPU/GPU位置有PCIe反證與tail-skip貢獻集合約束；GU/down pipeline已部署；arrival新增重疊上限僅0.62ms/w；MTP/spec有既有反例；新mainline功能先查適用性；本輪具體重用AVX-VNNI/gather並查實際row partition與conversion，不直接rebase全專案。
7. **失敗根因是否找到**：上一版權重排列可行，但沒有帶入現行ISA與P核查表，且多token編排/暫存器是否溢出未查；packing成本已量到。這些是工程缺口與機制假設，修同流程再測；不把「最佳格<1.3×」宣稱新核心不可能更快。

方向是先消除 R4 已知實作落差，再以實際 critical path 判定能否+10%。這輪不重掃結案旋鈕；若修完仍只有局部小收益，就清楚結案該候選，保留其他方向的獨立結果。

## 5. 主線執行順序與停止條件

### Phase 0：基準恢復、ledger 登記與 provenance

由 coordinator 以既有 launcher 恢復原 API，fresh verify binary/config/BEST/process/priority/capacity/env/idle。凍結候選範圍、每臂含義與採樣契約，在 EXPERIMENT_LEDGER 事前登記。保存 source/library/compiler hashes、base-relative patch、原始計畫；測試 directory 不覆蓋原 R4 run。若 API 原未啟動，記成「啟動既有 best」，不稱為原PID存活。

### Phase 1：VNNI 與 gather，先同 R4 佈局（已執行的部分另見下方狀態）

明確三臂：R0上輪R4、R1 R4+AVX-VNNI、R2 R4+AVX-VNNI+gather。這是受控 benchmark variants；不增加失敗後自動換舊kernel的 fallback。P/E 各自 fresh process、pin後才初始化ISA判斷；先檢查生成組語真的有對應指令，且沒有意外AVX512。

- 沿用同180unique experts／30選定層，五種GU類型與實際down pair、nt1/2/3。原native來源與metadata讀取不變，working set超過L3。每cell先3個輪替短pass，正確性全過且機制成立後同一次預註冊流程最多補足9paired pass；固定停止判準，不因中途顯著性無限加輪。
- 比較 GU-only 及 GU+activation quant+actual down。R1/R2要同時對R0及當輪現行native kernel，不能只證明比壞的舊R4快。保留每pass us、median、paired delta、dispersion、P/E variant ID。
- 每型整數替換先證明signedness與16/32-bit overflow邊界；尤其 maddubs16飽和與dpbusd32不可當成無條件等價。過不了等價驗證就停止該變更，不改量化範圍來掩飾。
- 停止：任何byte/decode/finite錯誤立刻停止並保留log；若正確但無對R0的機制收益，該變更記NO_GO。若所有候選的完整expert加權可行性連理想條件都不足目標且其餘成本只會增加，不做整機重build。

### Phase 2：nt2/3 編排與實際 row partitions

只對Phase1已能正確執行的基線，檢查nt2/3生成組語、stack traffic與register live ranges；不能未看組語就宣稱spill是根因。最多兩個事前選定結構變體：token loop展開／累加分組，保持四列共用解碼與相同權重，不掃十幾種unroll因子。每個變體3對短篩，機制與收益成立才最多9對。

以實際 pool source 計算row partition邊界、GU/down parts與對齊；先測生產會遇到的r0/r1及非整個640row區間，並處理4row邊界契約。不得新增丟row或隱含scalar fallback；若runtime不能保證邊界，明列需改pool的最小契約與成本。再以同核心/格式/nt分布估原pool影響，單核full-row不能取代多worker記憶體競爭測量。

### Phase 3：repack/inverse、消費者與同容量成本

先列 original CPU/GPU/SSD/prefill各消費者的資料格式、owner/lifetime、slot bytes與scratch。測pack與inverse的原始bytes/s、µs/expert、配置成本；最多一個直接SIMD bit permutation候選，各格式byte roundtrip必須零差異。量測不含比較/SHA的時間，也另報端到端配置成本。

現階段不做全42.9GB pack轉換。若原native GPU consumer需要inverse，按實際admission頻率計入；若缺頻率，用完整既有trace計數或一次最小diagnostic量測，不用猜值。若新增resident副本、偷減slots或未核對prefill consumer，停止integration。不能把「預先轉一次」當免費：記錄啟動成本、RAM/SSD byte budget、無轉換失敗fallback。

### Phase 4：瓶頸重算與候選選擇

把每項已測結果放回實際工作權重與I/O暴露模型，分開報GU、down、quant、dispatch/同步、conversion、critical path；重疊項不能相加。若缺joint format×nt×core分布，做一次最小DIAG取得，無資料時只列情境範圍。down若已限制整體收益，只量同現行down的多worker瓶頸，不直接新增稀疏、低精度或新down演算法。

候選進整機的必要條件：正確性通過、同容量消費者契約完整、扣新成本後有至少3.37ms/window量級的可行證據（以當輪window重算），或明確已測互補段足以填差距。數個候選百分比不能直接相加；組合必須實測。

### Phase 5：品質、短整機 A/B、正式確認

先做第6節品質與candidate-off identity檢查。通過後只建一個最小整合候選，current source獨立worktree/build，不覆蓋live/main。candidate-off若與current-best數學／設定不符，先查build差異，不繼續比較。

短篩：C/B/C（三個fresh blocks）×原Hermes10題×max512，全部原sampling；記accepted tok/s、每window時間/accepted tokens、CPU/GPU/IO、format/nt權重、容量/priority與工具輸出合法性。若B相對兩個C都不改善，或慢3%以上，停止；若只有1–3%且機制不足10%目標，記小收益不加碼。短篩只是選擇，不宣稱95%正式結論。

正式確認另開固定5輪C/B配對、輪序交錯，各block fresh engine、同10題×512。不得看到顯著就停、也不延長到顯著；只為品質/identity/process/fatal或使用者指令中止。primary按輪pooled accepted tok/s比值，secondary按題；報均值、95%paired t-CI(df4)、token/window/輸出長度差。mean≥10%且CI下限>0＝點估計達+10%但幅度仍不確定；只有CI下限≥10%才稱本測試以95%下界支持至少+10%。mean<10%或CI跨0則目標未確認。保存全部partial，不把未跑輪算成零或成功。
